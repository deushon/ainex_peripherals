# Инструкция по калибровке PID регулятора

## Быстрый старт

### 1. Установка зависимостей

```bash
pip install scipy
```

### 2. Включение калибровки

Откройте файл `config/walking.yaml` и установите:

```yaml
walking:
  stabilization_pid:
    calibration:
      enabled: true  # Включить калибровку
      start_delay: 5.0  # Задержка перед началом (секунды)
      duration: 60.0  # Длительность сбора данных (секунды)
      target_angle: 85.0  # Целевой угол (градусы)
      angle_range: 10.0  # Диапазон ±10° (75° - 95°)
```

### 3. Запуск калибровки

1. Запустите систему управления роботом
2. Через 5 секунд начнется автоматическая калибровка
3. **Ничего делать не нужно** - система все сделает сама!

### 4. Процедура калибровки (полностью автоматическая)

Система автоматически:

1. **Устанавливает минимальный угол** (target - range) и пытается его удержать
2. **Переключается на целевой угол** (center) и пытается его удержать
3. **Переключается на максимальный угол** (target + range) и пытается его удержать
4. **Повторяет цикл** несколько раз для сбора достаточного количества данных
5. **Собирает данные** о том, как PID контроллер реагирует на каждый угол
6. **Оптимизирует параметры** на основе собранных данных

**Пример**: При target_angle=85° и angle_range=5° система будет тестировать:
- 80° (минимум)
- 85° (центр)
- 90° (максимум)
- Повторяет цикл несколько раз

### 5. Завершение калибровки

После завершения сбора данных:
- Система автоматически оптимизирует параметры PID
- Результаты сохраняются в конфиг
- Установите `calibration.enabled: false` для использования откалиброванных значений
- Перезапустите систему

## Как это работает

### Алгоритм автоматической калибровки

Система использует стандартный подход для калибровки PID:

1. **Автоматическое тестирование**: Система сама устанавливает разные setpoints (целевые углы) через PID контроллер
2. **Сбор данных**: Во время удержания каждого угла собираются данные о поведении системы:
   - Текущий угол (pitch)
   - Выход PID контроллера
   - Ошибка стабилизации
3. **Оптимизация**: Используется метод **дифференциальной эволюции** для поиска оптимальных параметров:
   - Для каждого набора параметров вычисляется метрика качества (ISE - интеграл квадрата ошибки)
   - Алгоритм ищет параметры, минимизирующие ошибку стабилизации
4. **Сохранение**: Оптимальные параметры сохраняются как `calibrated_kp`, `calibrated_ki`, `calibrated_kd`

### Последовательность тестирования

Система автоматически переключает setpoint PID контроллера между тремя углами:
- **Минимум**: `target_angle - angle_range`
- **Центр**: `target_angle`
- **Максимум**: `target_angle + angle_range`

Каждый угол удерживается в течение `setpoint_duration` секунд, затем происходит переключение на следующий. Цикл повторяется несколько раз для сбора достаточного количества данных.

### Использование откалиброванных параметров

После калибровки в конфиге появятся:

```yaml
walking:
  stabilization_pid:
    calibrated_kp: 0.012345  # Автоматически заполняется
    calibrated_ki: 0.056789  # Автоматически заполняется
    calibrated_kd: 0.001234  # Автоматически заполняется
```

При `calibration.enabled: false` система автоматически использует эти значения вместо `kp`, `ki`, `kd`.

## Рекомендации

### Параметры калибровки

- **start_delay**: 5.0 секунд - задержка перед началом (дает время системе инициализироваться)
- **duration**: 60.0 секунд - общая длительность (определяет количество циклов тестирования)
- **setpoint_duration**: 10.0 секунд - время удержания каждого угла
- **target_angle**: 85.0° - целевой угол (рекомендуется для гуманоидных роботов)
- **angle_range**: 5.0° - диапазон ±5° (80° - 90°) - небольшой диапазон около рабочего угла

**Количество циклов** = `duration / (setpoint_duration * 3)`
- При duration=60 и setpoint_duration=10: 60/(10*3) = 2 цикла
- Каждый цикл тестирует 3 угла, итого 6 setpoints

### Когда проводить калибровку

- При первой настройке робота
- После изменения механики робота
- При изменении массы или центра масс
- Если стабилизация работает нестабильно
- Периодически (раз в несколько месяцев) для поддержания оптимальных параметров

## Устранение проблем

### Калибровка не запускается

- Проверьте, что `scipy` установлен: `pip install scipy`
- Убедитесь, что `calibration.enabled: true`
- Проверьте логи на наличие ошибок

### Недостаточно данных

- Увеличьте `duration` до 90-120 секунд (больше циклов тестирования)
- Уменьшите `setpoint_duration` до 8-10 секунд (больше точек данных)
- Проверьте, что IMU работает корректно и передает данные

### Плохие результаты калибровки

- Проведите калибровку повторно с большей длительностью
- Убедитесь, что робот стабилен и может удерживать разные углы
- Проверьте, что диапазон углов (angle_range) не слишком большой
- Убедитесь, что начальные параметры PID (kp, ki, kd) разумны

### Использование ручной настройки

Если автоматическая калибровка не подходит, можно настроить параметры вручную:

```yaml
walking:
  stabilization_pid:
    kp: 0.007  # Начните с малых значений
    ki: 0.087  # Добавьте для устранения постоянной ошибки
    kd: 0.001  # Добавьте для уменьшения колебаний
```

**Советы по ручной настройке**:
1. Начните с Kp = 0.001, Ki = 0, Kd = 0
2. Постепенно увеличивайте Kp до появления небольших колебаний
3. Добавьте Ki для устранения постоянной ошибки
4. Добавьте Kd для уменьшения колебаний
5. Увеличивайте параметры постепенно, проверяя стабильность

## Технические детали

### Метрика качества

Система минимизирует **ISE (Integral Square Error)**:
- Интеграл квадрата ошибки стабилизации
- Штраф за колебания выходного сигнала
- Обеспечивает плавную и стабильную работу

### Диапазоны поиска параметров

- **Kp**: 0.0001 - 0.1
- **Ki**: 0.0 - 0.5
- **Kd**: 0.0 - 0.01

Эти диапазоны можно настроить в коде, если необходимо.

### Алгоритм оптимизации

Используется метод **differential_evolution** из `scipy.optimize`:
- Глобальная оптимизация (не застревает в локальных минимумах)
- Надежный поиск оптимальных параметров
- Работает с нелинейными функциями качества
