# Модуль стабилизации

Единственное место для переопределения параметров ходьбы и позы робота на основе данных IMU.

## Структура

- `interfaces.py` - определения интерфейсов данных (IMUData, WalkingParams, StabilizationResult и т.д.)
- `stabilization.py` - основной модуль стабилизации (StabilizationModule)
- `converter.py` - утилиты для конвертации между форматами gait_manager и интерфейсами

## Использование

### Базовый пример

```python
from walking import StabilizationModule, IMUData, ThrottleData, WalkingParams
from walking import converter

# Создание модуля
stabilization = StabilizationModule()
stabilization.set_enabled(True)

# Подготовка данных IMU
imu_data = IMUData(
    orientation={'roll': 1.0, 'pitch': 2.0, 'yaw': 0.0},
    angular_velocity={'x': 0.0, 'y': 0.0, 'z': 0.0},
    linear_acceleration={'x': 0.0, 'y': 0.0, 'z': 9.8}
)

# Подготовка данных throttle
throttle_data = ThrottleData(x=0.01, y=0.0, angle=0.0)

# Получение текущих параметров из gait_manager
gait_param = gait_manager.get_gait_param()
period_time = [400, 0.2, 0.02]
move_amplitudes = {'x': 0.01, 'y': 0.0, 'angle': 0.0}

# Конвертация в WalkingParams
current_params = converter.gait_param_to_walking_params(
    gait_param, period_time, move_amplitudes
)

# Обработка стабилизации
result = stabilization.process(imu_data, throttle_data, current_params)

# Применение результата
if result.modified:
    updated_params = converter.apply_stabilization_result(current_params, result)
    # Конвертация обратно для gait_manager
    updated_gait_param = converter.walking_params_to_gait_param(updated_params)
    updated_period_time = converter.walking_params_to_period_time(updated_params)
    # Использование обновленных параметров
    gait_manager.set_step(updated_period_time, ...)
```

### Реализация логики стабилизации

В классе `StabilizationModule.process()` реализуйте свою логику:

```python
def process(self, imu_data, throttle_data, current_walking_params):
    result = StabilizationResult(modified=False)
    
    # Пример: корректировка позы на основе наклона
    roll = imu_data.orientation['roll']
    pitch = imu_data.orientation['pitch']
    
    if abs(roll) > 5.0:  # Если наклон больше 5 градусов
        result.pose_override = RobotPoseParams(
            init_roll_offset=-roll * 0.5,  # Коррекция
            init_pitch_offset=current_walking_params.pose.init_pitch_offset
        )
        result.modified = True
    
    return result
```

## Автоматическая калибровка PID регулятора

Система поддерживает автоматическую калибровку PID регулятора для стабилизации положения корпуса робота.

### Настройка калибровки

В файле `config/walking.yaml` настройте параметры калибровки:

```yaml
walking:
  stabilization_pid:
    calibration:
      enabled: true  # Включить режим калибровки
      start_delay: 5.0  # Задержка перед началом калибровки (секунды)
      duration: 60.0  # Длительность сбора данных (секунды)
      target_angle: 85.0  # Целевой угол для калибровки (градусы)
      angle_range: 10.0  # Диапазон углов ±10° (75° - 95°)
```

### Процесс калибровки (полностью автоматический)

1. **Подготовка**: Установите `calibration.enabled: true` в конфиге
2. **Запуск**: При запуске системы калибровка начнется автоматически через `start_delay` секунд
3. **Автоматическое тестирование**: Система сама устанавливает разные углы через изменение setpoint PID:
   - Минимальный угол: `target_angle - angle_range`
   - Целевой угол: `target_angle`
   - Максимальный угол: `target_angle + angle_range`
   - Каждый угол удерживается в течение `setpoint_duration` секунд
   - Цикл повторяется несколько раз
4. **Сбор данных**: Во время удержания каждого угла система собирает данные о поведении PID контроллера
5. **Оптимизация**: После сбора данных система автоматически оптимизирует параметры PID
6. **Сохранение**: Оптимальные параметры сохраняются в конфиг как `calibrated_kp`, `calibrated_ki`, `calibrated_kd`
7. **Использование**: При `calibration.enabled: false` используются последние откалиброванные значения

**Важно**: Никакого ручного вмешательства не требуется! Система все делает автоматически.

### Рекомендации по настройке

#### Диапазон углов для калибровки
- **Целевой угол**: 85° (рекомендуется для гуманоидных роботов)
- **Диапазон**: ±10° (75° - 95°)
- Это небольшой диапазон около рабочего угла, достаточный для настройки стабилизации

#### Длительность сбора данных
- **Минимум**: 30 секунд (для базовой калибровки)
- **Рекомендуется**: 60 секунд (для более точной настройки)
- **Максимум**: 120 секунд (для очень точной калибровки)

#### Процедура калибровки

1. **Подготовка робота**:
   - Убедитесь, что робот стоит устойчиво
   - IMU должен быть подключен и работать
   - Система стабилизации должна быть включена

2. **Запуск калибровки**:
   - Установите `calibration.enabled: true` в конфиге
   - Запустите систему управления роботом
   - Через 5 секунд начнется сбор данных

3. **Во время сбора данных**:
   - Аккуратно наклоняйте робота вперед и назад
   - Покрывайте весь диапазон от 75° до 95°
   - Удерживайте каждое положение 2-3 секунды
   - Избегайте резких движений

4. **После калибровки**:
   - Система автоматически сохранит параметры в конфиг
   - Установите `calibration.enabled: false` для использования откалиброванных значений
   - Перезапустите систему для применения новых параметров

### Алгоритм оптимизации

Система использует метод **дифференциальной эволюции** (differential evolution) из библиотеки `scipy.optimize` для поиска оптимальных параметров PID.

**Метрика качества**: Интеграл квадрата ошибки (ISE - Integral Square Error)
- Минимизирует ошибку стабилизации
- Учитывает перерегулирование и колебания
- Обеспечивает плавную и стабильную работу

**Диапазоны поиска параметров**:
- **Kp**: 0.0001 - 0.1
- **Ki**: 0.0 - 0.5
- **Kd**: 0.0 - 0.01

### Требования

Для работы калибровки необходимо установить:
```bash
pip install scipy
```

### Ручная настройка PID

Если автоматическая калибровка не подходит, можно настроить параметры вручную в `config/walking.yaml`:

```yaml
walking:
  stabilization_pid:
    kp: 0.007  # Пропорциональный коэффициент
    ki: 0.087  # Интегральный коэффициент
    kd: 0.001  # Дифференциальный коэффициент
```

**Рекомендации по ручной настройке**:
1. Начните с малых значений Kp (0.001 - 0.01)
2. Добавьте Ki для устранения постоянной ошибки (0.01 - 0.1)
3. Добавьте Kd для уменьшения колебаний (0.0001 - 0.01)
4. Увеличивайте параметры постепенно, проверяя стабильность

## Важные моменты

1. **Единственное место переопределения**: Все изменения параметров ходьбы должны проходить через `StabilizationModule`

2. **Если не переопределяете**: Верните `StabilizationResult(modified=False)` или `None` для override полей - будут использованы значения из конфига

3. **Интерфейсы четко определены**: Используйте типизированные структуры из `interfaces.py` для всех данных

4. **Конвертеры**: Используйте функции из `converter.py` для преобразования между форматами gait_manager и интерфейсами

5. **Калибровка PID**: Используйте автоматическую калибровку для оптимальной настройки стабилизации
