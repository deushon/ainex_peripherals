# ROS API Документация для серверной части

## 📋 Обзор

Этот документ описывает все ROS топики, сервисы и форматы сообщений, которые использует ROS нода `joystick_control` для взаимодействия с серверной частью игры.

---

## 📤 Топики, публикуемые ROS нодой (для чтения сервером)

### 1. `/game/robot_hp` (публикуется ROS нодой)
- **Тип**: `std_msgs/Int32`
- **Описание**: Текущее значение HP робота
- **Частота публикации**:
  - **КРИТИЧНО**: Сразу после получения урона (в `damage_callback`)
  - Периодически: каждые 0.5 секунды (2Hz) для синхронизации
- **Диапазон значений**: 0-100
- **Пример**: `data: 75`

**Важно**: Сервер должен подписаться на этот топик для отслеживания HP и автоматического завершения матча при HP=0.

---

### 2. `/game/hit_detection` (публикуется ROS нодой)
- **Тип**: `std_msgs/String` (JSON)
- **Описание**: Сообщение о попадании, обнаруженном датчиками робота
- **Формат JSON**:
```json
{
  "robot_id": "robot_1",
  "timestamp": 1234567890.123,
  "hit_detected": true
}
```
- **Поля**:
  - `robot_id` (string): ID робота, который обнаружил попадание
  - `timestamp` (float): Время обнаружения (ROS time)
  - `hit_detected` (bool): Всегда `true` в текущей реализации

---

### 3. `/game/firing_state` (публикуется ROS нодой)
- **Тип**: `std_msgs/Bool`
- **Описание**: Состояние стрельбы робота
- **Значения**:
  - `true`: Робот стреляет
  - `false`: Робот не стреляет

---

### 4. `/game/robot_status` (публикуется ROS нодой)
- **Тип**: `std_msgs/String` (JSON)
- **Описание**: Общий статус робота с различными типами событий
- **Формат JSON**:
```json
{
  "robot_id": "robot_1",
  "status_type": "hp_zero_locked",
  "hp": 0,
  "locked": true,
  "timestamp": 1234567890.123
}
```
- **Поля**:
  - `robot_id` (string): ID робота
  - `status_type` (string): Тип события (см. ниже)
  - `hp` (int): Текущее HP
  - `locked` (bool): Заблокирован ли робот
  - `timestamp` (float): Время события (ROS time)
- **Возможные значения `status_type`**:
  - `"hp_zero_locked"`: HP достигло 0, робот заблокирован
  - `"hp_reset"`: HP сброшено на 100 (начало нового матча)
  - `"permissions_changed"`: Изменились разрешения управления
  - `"lock_changed"`: Изменилось состояние блокировки (legacy режим)
  - `"unlock_changed"`: Робот разблокирован (legacy режим)

## 📥 Топики, на которые подписывается ROS нода (для публикации сервером)

### 1. `/game/validated_damage` (публикуется сервером)
- **Тип**: `std_msgs/Int32`
- **Описание**: Валидированный урон, который должен быть применен к роботу
- **Обработка в ROS ноде**:
  - Если `data <= 0`: игнорируется
  - Если `data > 0`: вычитается из текущего HP
  - **КРИТИЧНО**: После применения урона сразу публикуется обновленное HP в `/game/robot_hp`
- **Пример**: `data: 25` (робот получит 25 урона)

**Важно**: После публикации урона сервер должен ожидать обновление HP в топике `/game/robot_hp`.

---

### 2. `/game/match_start` (публикуется сервером) ⭐ НОВОЕ
- **Тип**: `std_msgs/Bool`
- **Описание**: Сигнал начала нового матча
- **Обработка в ROS ноде**:
  - Если `data == true`: 
    - HP сбрасывается на 100
    - Робот разблокируется
    - Все разрешения восстанавливаются
    - Публикуется обновленное HP
- **Пример**: `data: true` (начать новый матч)

**Рекомендация**: Публиковать `true` при начале каждого нового матча для автоматического сброса HP.

---

### 3. `/game/control_lock` (публикуется сервером) - Legacy
- **Тип**: `std_msgs/Bool`
- **Описание**: Полная блокировка/разблокировка управления (legacy режим)
- **Обработка в ROS ноде**:
  - Если `data == true`: полная блокировка (кроме камеры)
  - Если `data == false`: полная разблокировка
- **Примечание**: Игнорируется, если используется детальная система разрешений (`/game/control_permissions`)

---

### 4. `/game/control_permissions` (публикуется сервером) - Рекомендуется
- **Тип**: `std_msgs/String` (JSON)
- **Описание**: Детальные разрешения управления роботом
- **Формат JSON**:
```json
{
  "movement": true,
  "head": true,
  "firing": true,
  "camera": true
}
```
- **Поля** (все опциональные, обновляются только указанные):
  - `movement` (bool): Разрешено ли движение
  - `head` (bool): Разрешено ли управление головой
  - `firing` (bool): Разрешено ли стрельба
  - `camera` (bool): Разрешен ли доступ к камере (обычно всегда `true`)
- **Примечание**: Можно отправлять только нужные поля, остальные не изменятся.

## 🔧 Сервисы (для вызова сервером)

### 1. `/game/robot_health` (вызывается сервером)
- **Тип**: `std_srvs/Trigger`
- **Описание**: Проверка состояния робота
- **Запрос**: Пустой (`TriggerRequest`)
- **Ответ**: `TriggerResponse`
  - `success` (bool): Успешность запроса
  - `message` (string): JSON строка с данными о здоровье
- **Формат JSON в `message`**:
```json
{
  "available": true,
  "hp": 75,
  "locked": false,
  "connected": true,
  "robot_id": "robot_1"
}
```
- **Поля**:
  - `available` (bool): Доступен ли робот
  - `hp` (int): Текущее HP (0-100)
  - `locked` (bool): Заблокирован ли робот
  - `connected` (bool): Подключен ли Arduino
  - `robot_id` (string): ID робота

---

### 2. `/game/reset_hp` (вызывается сервером) ⭐ НОВОЕ
- **Тип**: `std_srvs/Trigger`
- **Описание**: Принудительный сброс HP на 100
- **Запрос**: Пустой (`TriggerRequest`)
- **Ответ**: `TriggerResponse`
  - `success` (bool): Успешность запроса
  - `message` (string): Сообщение о результате
- **Действия при вызове**:
  - HP сбрасывается на 100
  - Робот разблокируется
  - Все разрешения восстанавливаются
  - Публикуется обновленное HP

**Примечание**: Альтернатива топику `/game/match_start`, если нужен более явный контроль.

---

## 🔄 Последовательность работы с HP

### Сценарий 1: Робот получает урон
1. Сервер публикует урон в `/game/validated_damage` (например, `data: 25`)
2. ROS нода получает урон, вычитает из HP
3. **КРИТИЧНО**: ROS нода сразу публикует обновленное HP в `/game/robot_hp`
4. Если HP <= 0:
   - Робот блокируется
   - Публикуется статус `"hp_zero_locked"` в `/game/robot_status`
5. Сервер читает обновленное HP и может завершить матч

### Сценарий 2: Начало нового матча
1. Сервер публикует `true` в `/game/match_start`
2. ROS нода:
   - Сбрасывает HP на 100
   - Разблокирует робота
   - Восстанавливает все разрешения
   - Публикует HP=100 в `/game/robot_hp`
   - Публикует статус `"hp_reset"` в `/game/robot_status`

### Сценарий 3: Периодическая синхронизация
- ROS нода автоматически публикует HP каждые 0.5 секунды (2Hz) в `/game/robot_hp`
- Сервер может использовать это для синхронизации состояния

---

## ⚠️ Критически важные моменты

1. **Публикация HP после урона**: ROS нода публикует HP **сразу** после получения урона. Сервер должен подписаться на `/game/robot_hp` для получения обновлений.

2. **Автоматическое завершение матча**: При HP=0 робот блокируется автоматически. Сервер должен отслеживать `/game/robot_hp` и завершать матч при HP=0.

3. **Сброс HP**: Используйте `/game/match_start` (топик) или `/game/reset_hp` (сервис) для сброса HP при начале нового матча.

4. **Периодическая синхронизация**: HP публикуется каждые 0.5 секунды для синхронизации, даже если урон не получен.

## 📝 Примеры использования (Python/rospy)

### Подписка на HP от ROS ноды:
```python
import rospy
from std_msgs.msg import Int32

def hp_callback(msg):
    hp = msg.data
    print(f"Robot HP: {hp}")
    if hp <= 0:
        print("Match should end!")

rospy.init_node('server_node')
hp_sub = rospy.Subscriber('/game/robot_hp', Int32, hp_callback)
rospy.spin()
```

### Публикация урона в ROS ноду:
```python
from std_msgs.msg import Int32

damage_pub = rospy.Publisher('/game/validated_damage', Int32, queue_size=10)
damage_msg = Int32()
damage_msg.data = 25
damage_pub.publish(damage_msg)
```

### Начало нового матча:
```python
from std_msgs.msg import Bool

match_start_pub = rospy.Publisher('/game/match_start', Bool, queue_size=10)
match_start_msg = Bool()
match_start_msg.data = True
match_start_pub.publish(match_start_msg)
```

### Проверка здоровья робота:
```python
from std_srvs.srv import Trigger
import json

rospy.wait_for_service('/game/robot_health')
health_service = rospy.ServiceProxy('/game/robot_health', Trigger)
response = health_service()
if response.success:
    health_data = json.loads(response.message)
    print(f"Robot HP: {health_data['hp']}")
```
